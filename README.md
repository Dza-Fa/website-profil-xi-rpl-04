## Projek manager - Dzakiir

### 1. Apa perbedaan bekerja sendiri dengan menggunakan Git dan GitHub?

Git dan GitHub memungkinkan tim bekerja secara terstruktur dengan branch, riwayat commit, Pull Request, dan Code Review. Setiap perubahan dapat dilacak serta digabungkan tanpa harus saling menimpa file secara manual.

### 2. Apa manfaat branch?

Branch memisahkan pengerjaan fitur dari branch `main`. Dengan begitu, fitur baru atau eksperimen dapat dikembangkan tanpa mengganggu versi utama yang tetap stabil.

### 3. Mengapa Pull Request diperlukan?

Pull Request menjadi ruang untuk mengajukan perubahan, mendiskusikannya, dan memastikan kode sudah sesuai sebelum digabungkan ke branch `main`.

### 4. Apa manfaat Code Review?

Code Review membantu menemukan bug, typo, masalah struktur HTML, dan ketidakkonsistenan tampilan sebelum perubahan masuk ke versi utama. Proses ini juga membuat kualitas kode lebih terjaga.

### 5. Error apa yang paling sulit diselesaikan?

Merge conflict dan error `git push rejected` termasuk masalah yang menantang karena membutuhkan pemeriksaan riwayat perubahan serta koordinasi dengan anggota tim lain.

### 6. Bagaimana solusi ditemukan?

Solusi dicari dengan membaca pesan error di terminal, memeriksa status dan riwayat Git, berdiskusi dengan anggota terkait, lalu menguji kembali website setelah konflik atau perubahan diselesaikan.

### 7. Apa kontribusi terbesar kalian dalam kelompok?

Sebagai Project Manager, kontribusi terbesar saya adalah memrakarsai dan mengkonfigurasi repository GitHub, membagi peranan dan branch kerja tim, membuatkan landasan design system menggunakan Tailwind CSS, mengevaluasi seluruh Pull Request lewat Code Review, serta memandu tim hingga seluruh fitur terintegrasi dengan sukses tanpa merusak branch main.

### 8. Jika menjadi programmer profesional, kebiasaan apa dari kegiatan ini yang akan kalian pertahankan?

Saya akan mempertahankan kebiasaan tidak pernah melakukan commit/push langsung ke branch main, selalu menggunakan branch fitur tersendiri, membuat pesan commit yang deskriptif dan bermakna, serta disiplin melakukan Code Review dan komunikasi terbuka dengan anggota tim sebelum menggabungkan kode.

Developer profile - Anggun

1. Sendiri vs Git & GitHub:Sendiri rentan kode tertimpa/hilang dan riwayat manual; Git/GitHub mencatat riwayat perubahan otomatis, aman di cloud, dan mendukung kolaborasi tim.
2. Manfaat Branch:Mengisolasi fitur baru/eksperimen agar tidak merusak kode utama yang stabil.
3. Mengapa PR Diperlukan: Sebagai pintu gerbang pemeriksaan kode sebelum digabungkan ke cabang utama.
4. Manfaat Code Review: Menjaga kualitas kode, menemukan bug lebih cepat, dan meratakan pengetahuan dalam tim.
5. Error Tersulit:Merge Conflict (saat dua orang mengubah baris kode yang sama di berkas yang sama).

7. Kontribusi Terbesar: Merapikan struktur repository, memandu (branching),dan membantu menyelesaikan konflik kode.

Developer kontak - Syauki

1. Apa perbedaan bekerja sendiri dengan bekerja menggunakan Git dan GitHub?

Bekerja sendiri: Perubahan kode ditimpa secara manual, riwayat revisi tidak tertata rapi, dan rawan kehilangan data jika terjadi kesalahan.

Menggunakan Git & GitHub: Semua perubahan kode tercatat dalam riwayat (commit history), pengerjaan fitur bisa dilakukan secara paralel tanpa mengganggu kode utama, serta memudahkan kolaborasi tim.

2. Apa manfaat branch?

Memungkinkan pengembangan fitur baru, perbaikan bug, atau eksperimen dilakukan di ruang terisolasi tanpa merusak atau mengganggu kode utama (main/master branch).

3. Mengapa Pull Request diperlukan?

Untuk mengajukan penggabungan kode (merge) dari satu branch ke branch utama. Proses ini memastikan kode ditinjau lebih dahulu oleh anggota tim lain sebelum resmi digabungkan.

4. Apa manfaat Code Review?

Membantu mendeteksi kesalahan atau bug lebih awal, menjaga standar kualitas kode, serta menjadi sarana saling belajar dan berbagi pengetahuan antaranggota tim.

5. Error apa yang paling sulit kalian selesaikan?

Merge conflict saat menggabungkan dua branch yang mengubah bagian baris kode yang sama. (Bisa disesuaikan dengan pengalaman pribadi).

6. Bagaimana kalian menemukan solusinya?

Menelaah baris kode yang berkonflik bersama rekan tim, memilih bagian kode yang benar, berdiskusi, serta mencari referensi panduan di dokumentasi Git atau internet. (Bisa disesuaikan dengan pengalaman pribadi).

7. Apa kontribusi terbesar kalian dalam kelompok?

Membantu menyelesaikan konflik penggabungan kode (merge conflict), membuat struktur branch, atau mengimplementasikan salah satu fitur utama dalam proyek kelompok. (Isi sesuai dengan peranmu).

8. Jika menjadi programmer profesional, kebiasaan apa dari kegiatan ini yang akan kalian pertahankan?

Kebiasaan melakukan commit secara berkala dengan pesan (commit message) yang jelas, selalu menggunakan branch baru untuk fitur baru, serta rutin melakukan code review sebelum gabungkan kode.
